# Agent smoke trials, 2026-11-15

Two fresh Claude Code sessions, each started in an app made with `ctzd new --offline` (CLI 0.6.0), with nothing but
the app's own guidance (`AGENTS.md`, the skills) and a business user's request. They were run with
`--setting-sources project,local --strict-mcp-config`, so no personal settings, hooks or MCP servers reached them.
The person's side was played by the platform agent, answering only what the trial agent asked. This is a smoke
trial before the work clone, not section 15's step 6: two runs, one model each, judged by hand.

## The requests

- **Dashboard, Fixed Income kit, Opus.** "For a date I pick, I want to see our positions grouped by sector: how much
  market value and DV01 each sector has, with the totals for the whole book across the top, and a bar chart of market
  value by sector. If I click on a sector I'd love to see just its bonds underneath, but that's a nice-to-have. The
  real database isn't connected on my laptop yet, so the sample data is fine for now."
- **Job, Multi-Asset kit, Sonnet.** "Every weekday morning I'd like an email to me summarising yesterday's trades by
  desk: how many trades each desk did and their total notional, as a table in the email, with the same table
  attached as a spreadsheet."

Both were then told "Looks good, thanks! Yes please, send it to dev so a colleague can review it."

| Questions asked | none | three, in business words: the data has portfolios, not desks (answer: portfolio = desk); who gets it (the owner); when (07:00 London) |

| Result | `/` "Sectors": as-of date, three stats, a bar chart and a sector grid side by side, a bonds grid with a sector select; clicking a bar or a sector row sets the select | `trade_summary` job on `mas_trades`, weekdays 07:00 London, the table in the body and as `.xlsx`, written to the store too |
| `ctzd check` | passed (after three rounds of ty findings in its page test) | passed |
| Independently checked | `scripts/browser_check.py`: passes light and dark, the select against `ctzd render`; a real click on the Treasury bar showed its 8 bonds and on the Municipal row its 6 | `ctzd run trade_summary --local`: one email to the owner, dated subject, table and attachment |
| Asked to deploy | ran `ctzd deploy`, read "not built yet", told the person plainly that it runs only on their laptop for now | the same, and offered the saved email to show a colleague; made no commits and did not try git by hand |

Both stayed inside the rules: reads only through the kit and `ui.load`, logic in `logic/`, the template's sample
removed, no suppressions, nothing committed, and each said what it had not verified (the dashboard agent: the click
in a real browser; the job agent: the real `mas_trades` rows).

## What the trials found, and the fixes

1. **Commands the guidance names did not exist.** `ctzd deploy`, `env`, `open`, `promote`, `rollback`, `releases`,
   `status`, `logs` and `delete` arrive in step 7, so an agent got argparse's "invalid choice". They now answer that
   they are not built yet and what to do meanwhile (run it here with `ctzd dev` or `ctzd run --local`; build on the
   sample rows). Both agents relayed that well when asked to deploy.
2. **`ctzd sources SOURCE` refused a source with no credentials**, pointing at `ctzd env`. It now lists the source's
   loaders and the columns of their rows, which is what the agent needed.
3. **Page tests fought ty**: a callback answers `tuple[object, ...]`, so reading a grid's rows back needed a cast.
   `ui.grid_rows(answer)` gives the rows typed; the template's test and the ctzd-pages skill use it.
4. **Click-to-filter took digging** (the agent read dash-ag-grid's JavaScript for `cellClicked`). The ctzd-pages skill
   now has the pattern, proven in the browser: a select holds the choice, one small callback turns a bar's
   `clickData` or a grid's `cellClicked` into its value.
5. **An email table's headers were the frame's column names** (`desk`, `notional`), and its caption wrapped its date.
   `ctzd_common.email` and `slack` now head a column as a page's grid does by default ("Market value"), and the
   caption does not wrap.
6. **The job agent ran a bare `python`**, which a desktop does not have. AGENTS.md now says Python runs through ctzd.

Left as they are: the job counts a weekday with no trades as a failed run (the agent said so; the person can change
it), and sums notional across currencies without converting (the agent flagged it).
